# SunnyNet 实测对照数据（含不利结果）

这是我自己项目的技术讨论帖，把当前所有可复核的实测结果放出来，
**包括输给同行、跑不动的部分**。所有数字取自仓库 `experiments/results/*.json`，
可逐条复跑。

## 项目是什么

一个原创的 O(N) 线性递推序列架构，目标是 CPU 上高效训练。
不是 Transformer / RNN / Mamba / CNN 的移植。

状态更新形式：`s_t = p_t · s_{t-1} + (1 - p_t) · u_t`，
`p` 由对数均匀多尺度 horizon 与**组内成对竞争门控**
（`sigmoid(g_i-g_j)·sigmoid(g_i-g_k)`）共同决定，取代 softmax。
另外有深度可分因果卷积、三抽头循环状态滤波、特征残差流。

递推形式与线性注意力类工作有亲缘性，这点我在 README 里直接写明。

## 赢的部分（实测）

**1. 长序列前向延迟**：batch=1、8 线程、约 365k 参数栈、每格独立子进程、9–15 次中位
（`seq_scaling.json`）：

| T | SunnyNet | Transformer | 倍数 | IQR |
|---|---|---|---|---|
| 512 | 26.4 ms | 40.8 ms | 1.55× | 12.4%/6.0% |
| 1024 | 50.0 ms | 141.2 ms | 2.83× | 6.3%/6.6% |
| 2048 | 98.1 ms | 638.2 ms | 6.51× | 6.7%/6.3% |
| 4096 | **148.7 ms** | **3373.4 ms** | **22.69×** | 3.9%/2.7% |

注意：这是**纯前向延迟**，不是训练吞吐。

**2. 20M 规模质量**：栈参数对齐、同语料、200 步、T=256：

## 输的部分（实测，请一并看）

- **训练步（前向+反向）仍比 Mamba/H3/Hyena 慢**：20M 慢 8–37%，1.4M 慢 20–52%，
  到 T=4096 都没有交叉点。22.7× 是前向延迟比。
- **短序列不行**：与 Transformer 交叉点约 T≈384，短于它更慢。
- **100M 规模质量退回第二**：p100mw（栈 93.8M）、T=256、100 步，
  rwkv 105.66 / SunnyNet 109.47 / h3 128.13。**20M 的第一没延续**，
  所以我不敢说"规模越大越有优势"。
- **100M 下统一 lr 会让同行发散**：lr=3e-3 时 mamba 在 step 37 NaN、
  hyena 梯度范数到 41.5。这是我对照协议的缺陷（lr 未逐架构调优），
  正在用 lr=1e-3 补跑。
- **0.5B 基本跑不动**：481M 栈参数在 15.9GB 内存的 CPU 上实例化直接 OOM。
  换到 6GB 的 GTX 1060 上，前向和最朴素的 SGD 能跑，但 **AdamW、带动量的 SGD
  全部 OOM**；而且 T=128 时三次运行只有一次通过，另两次第一步反向就失败
  （WDDM 显存分配悬崖）。跑通的 30 步里 loss 在噪声内震荡，**拿不到任何质量数据**。

## GPU 上的一些观察（顺手测的）

- 架构没做任何 CUDA 特化改写就能在 CUDA 上跑（扫描用 cumsum/exp，门控用 sigmoid）。
  B=8：前向加速 8.0–15.2×、训练步 9.9–12.5×。**这是没做任何 CUDA 侧优化的下界**，
  不代表 GPU 上性能好，我没做同行 GPU 对照。
- **GPU 上算子剖析反而说明融合更不值得**：CUDA kernel 级看，扫描类占前向 1.85%、
  竞争门控占 2.55%（CPU 上前向这两段加起来约 31.6%）。GPU 上被 GEMM 稀释了，
  最大单项 `aten::mm` 也才 16%。所以我把融合这条线停了。
- **一个教训**：把门控的 `roll` 换成 `index_select`，纯算子微基准快
  （cuda 0.717×、cpu 0.891×，数值完全等价），但**端到端两平台都测不出差异**
  （cuda 5.8% 落在轮间 13.5% 的极差里，cpu 0.2%）。我按端到端判定，没改。
  微基准单独的结论不可信——这个坑我踩了两次。

## 两个可能对别人有用的发现

1. **参数对齐下层数会失控**：按计算栈参数对齐时，低秩窄模型被迫堆很多层
   （20M 下 10 层 vs 同行 5–7 层）。重平衡到 `dim 512→640, L 10→6`，
   同等参数量下训练快 12.1%、ppl 好 10.9%、内存省 14%。
2. **CPU 上算子融合的收益上界**：把扫描与竞争门控都替换成极简算子（数值不等价），
   量出"完全融合"的端到端上限只有 8.8%。因为反向占了训练步约 65%。
   本机 `torch.compile` 不可用（MSVC 在，Windows SDK 头文件缺失）；
   GPU 侧也没有 nvcc / CUDA toolkit / triton，两边的融合路线都走不通。
